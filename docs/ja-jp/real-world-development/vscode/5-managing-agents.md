Copilot をエージェント モードにすると、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または却下し、エディターを離れずに追加プロンプトで作業を調整・拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントへ指示し、ハイ コントラスト モードとともにライト モードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加してほしいという依頼がありました。新しい会話を始めずに、既存のセッションに追加指示を伝えます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行うファイルの調査、コマンドの実行、編集の提案が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中に Chat をスクロールし、ツール呼び出しを確認します。ファイルの読み取り、編集、実行許可を求めるターミナル コマンドなどが表示されます。
3. ファイル編集が提案されたら、差分がインラインで表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消して再度試させるには **Undo** を選択します。
4. Chat 上部の **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行など、ツールの許可を求められることがあります。エージェントは停止して **Allow** を表示するため、内容を確認してから許可します。

5. エージェントがハイ コントラスト モードを実装し、変更を要約するまで待ちます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えも追加します。会話を続けることで、エージェントは以前の作業、変更したコンポーネント、スタイル、local storage の使い方を保持します。

1. Copilot Chat の入力欄に次のプロンプトを送ります。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI を意図しない方法でリファクタリングする場合) は、Chat 入力欄の横にある **Stop** で停止し、明確な追加指示を送ります。

> [!TIP]
> 進行中のセッションへの追加指示は、最初からやり直すよりも迅速です。追加プロンプトで調整 ("CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う")、方向修正 ("切り替えを 3 つに増やさず、既存の設定パネルにライト モードを統合する")、範囲の拡張 ("両方の切り替えにキーボード ショートカットを追加する") を依頼できます。

## 作業セットをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ方針を反映した ARIA 属性、キーボード操作、セマンティック HTML、local storage による永続化を確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視し、各ファイルの編集をレビューして採用または却下し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加プロンプトでセッションの進行中に指示を伝えました。

次の[レッスン][next-lesson]では、アクセシビリティ作業をプル リクエストとして公開し、このラボでローカルのカスタム エージェントが生成した変更をレビューします。
